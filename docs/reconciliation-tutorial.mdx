This tutorial walks through a monthly bank reconciliation using a Grok Bot agent.

<Info>
 The agent will:

1. Prepare the month's Google Drive folder and Google Sheet import the bank CSV data
2. Fill the reconciliation columns and categorise each transaction
3. Seed Categories and Counterparty reference tabs from those Bank rows
4. Verify totals
5. Match any invoices that you have either received via an email or that you have manually uploaded with the bank transactions.
6. Save links to the invoices in your Google Drive
</Info>

## Try with test data

After Quick start, you can exercise the skill **without** exporting a live bank CSV or searching your Gmail inbox. Ask the agent to run bank reconciliation in **test mode** (or “try with sample / test data”).

Test mode still creates a Google Sheet under your Drive root for **November 2024** (from the skill `.xlsx` template on a first month, or a copy of the prior month), imports a fixture CSV, seeds Categories / Counterparty reference tabs from the filled Bank rows, matches four sample invoice `.eml` files (with PDF attachments) from `skills/bank-reconciliation/test-data/`, and uploads expense PDFs with Invoice links. It does **not** read Gmail. Compare the agent’s report to `skills/bank-reconciliation/test-data/expected-results.md`.

When you are ready for a real month, continue with the live CSV export steps below.

## Export your monthly bank statement

All banks should have an option to export bank transactions. 

- Export last month's bank statement as a CSV and save the file to your computer.

The skill maps common bank CSV layouts, so the agent can import statements even when column names vary by bank.

<Info>
  A **CSV** (Comma-Separated Values) file is a plain-text spreadsheet: each row is a transaction, and columns such as date, amount, and description are separated by commas. Banks use CSV so you can open the statement in Sheets or Excel and so the agent can import the data into your reconciliation workbook.
</Info>

<Tip>
  Automating monthly bank pulls is possible later, but only with tightly restricted access. For this tutorial, export a CSV by hand — simpler and safer.
</Tip>

## Run the Reconciliation Skill

## Prepare the month's folder and sheet

<Steps>
  <Step title="Create year and month folders">
    Under your Drive root, ensure the year folder exists for the statement year, including an extracts subfolder. Then create the month folder for the statement month (`YYYYMM`) if it is missing.
  </Step>
  <Step title="Locate the bank CSV">
    Look for the CSV under `root / year / extracts / month`. If it is missing, obtain it from the operator and save it into that folder before importing.
  </Step>
  <Step title="Start from last month's sheet (or upload the skill template)">
    Look for the previous month's reconciliation sheet. If it exists, copy it into this month's folder so reference tabs stay current: `Counterparty-Match`, `Counterparties`, `Counterparty-Category`, `Email matching`, and `Categories`.

    On the copy only, clear last month's transaction rows and the raw CSV area on the transactions tab. Keep the header row and all reference tabs. Never edit last month's sheet in place.

    If no previous sheet exists (first month), upload a copy of the scrubbed template `skills/bank-reconciliation/Y[date]_[company]_Reconciliation.xlsx` into this month's folder, rename it from the sheet title pattern, and convert it to a native Google Sheet. Keep the template's tab visibility. Do not create a blank spreadsheet from scratch or edit the repo template in place.
  </Step>
</Steps>

## Inspect the layout

Before writing, confirm tab names and column headers. Tabs usually include:

- Transactions tab (main reconciliation grid)
- `Categories` — allowed category spellings
- `Counterparty-Match` — formatted name ↔ raw bank name
- `Counterparties` — unique formatted names
- `Counterparty-Category` — formatted name ↔ category
- `Email matching` — Gmail search rules per counterparty

On the transactions tab, locate columns by header name. Typical layout:

`Date | Recipient / Payer | Category | Credit | Debit | Invoice | Note` then the raw CSV area to the right.

## Import the CSV

Paste the CSV into the first empty column to the right of the reconciliation columns (often starting at column H). If the template already has raw CSV headers there, keep them and write data from row 2; otherwise put headers in row 1 and data from row 2. Write numbers as numbers and dates as real dates.

After writing the import, hide every imported raw CSV column (typically H onward). Keep the seven reconciliation columns visible. The agent may still read the hidden columns when filling or matching; do not unhide them unless the operator asks.

## Fill the reconciliation columns

Create one reconciliation row per CSV row.

| Column | How to fill it |
| --- | --- |
| **Date** | Transaction date as a real date, display format `d-mmm` (for example `5-Nov`) |
| **Recipient / Payer** | Prefer Merchant, else Payee Name, else Payer Name, else Description. Loose-match against `Counterparty-Match`. If no match, write a clean, properly cased name |
| **Category** | Look up the formatted name in `Counterparty-Category`. Otherwise pick from `Categories`. If those tabs have no data rows yet (first month), invent a short consistent category — do not leave Category blank |
| **Credit** | Absolute amount if money came in; otherwise blank |
| **Debit** | Absolute amount if money went out; otherwise blank |

Clear any leftover formulas or junk below the last data row.

## Seed reference tabs

In the same run, after filling Bank, seed (or extend) the reference tabs from those rows and the raw bank string for each counterparty:

- `Categories` — unique Category values from Bank
- `Counterparty-Match` — formatted `Recipient / Payer` ↔ raw `Match` string
- `Counterparties` — unique formatted names
- `Counterparty-Category` — formatted name ↔ Category used on Bank

Skip keys that already exist (later months). Do not unhide the tabs unless the operator asks.

## Verify and report

- Row count should match the CSV
- Dates should display as `d-mmm`
- `SUM(Credit)` and `SUM(Debit)` should match the CSV totals in and out
- The four reference tabs above should have data rows consistent with Bank (not header-only after a first fill)

Report the sheet link, totals, category counts, that reference tabs were seeded or updated, and any guesses (new counterparties or unsure categories).

## After review

When the operator says they have finished editing Category or Counterparty names:

1. Sync `Counterparty-Match` (formatted name ↔ raw Match string) without duplicates
2. Sync unique names into `Counterparties`
3. Sync `Counterparty-Category` and unique spellings into `Categories`
4. If a counterparty was renamed, update `Email matching` so invoice rules still line up

## Match invoices from email

Run this when the operator asks, or as a final optional step for debit rows.

<Steps>
  <Step title="Search with Email matching rules">
    For each debit row, check `Email matching` first. If the recipient is listed, search Gmail with that rule, narrowed by date and amount.
  </Step>
  <Step title="Fall back to a general search">
    Otherwise search by counterparty name, raw merchant text, a window of about two weeks before to a few days after the bank date, and the amount (include original FX amounts from the raw CSV when relevant).
  </Step>
  <Step title="Attach the invoice">
    Prefer a PDF attachment. Upload to an expenses subfolder inside the spreadsheet's folder as `YYYY-MM-DD_Counterparty_Amount.pdf`. Put a Drive hyperlink in **Invoice** whose **visible label is that filename** (not the raw URL), and format **Invoice** with **Clip** overflow (not Wrap). Add a **Note** only when something needs attention (FX/VAT mismatch, multi-charge invoice, uncertain match, and similar).

    Immediately save or update the working Gmail rule in `Email matching`. Skip bank-fee rows unless an invoice clearly exists. Never send, reply to, or change emails.
  </Step>
</Steps>

Report the expenses folder link, matches found, notes written, and rows still missing an invoice.

## Hand back

Tell the operator they may update Category names or Counterparty names directly on the spreadsheet. When they are finished, they should let the agent know so it can verify everything and correctly relink the reference tabs (`Counterparty-Match`, `Counterparties`, `Counterparty-Category`, `Categories`, and `Email matching` if names changed).
